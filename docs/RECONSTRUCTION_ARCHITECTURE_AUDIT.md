# 重建架构审查

审查日期为 2026-09-05。对象是当前工作区，包括已有未提交修改。最初阶段仅记录审查结果，用户随后要求继续修复。文末的实施记录说明当前已完成的代码修复和验证范围。前文问题描述保留发现时的行为，不能视为修复后的实时缺陷清单。

## 核心判断

当前架构保留了合理的职责划分。Agent 应当决定语义归属、设计意图、原生与图片的边界和视觉验收。问题在于，系统同时把大量低层参数反求交给 Agent，却没有提供足够可靠的测量候选、渲染反馈和局部修复工具。

生成阶段输出扁平图片。原生对象树、字体、文字基线、透明层和被遮挡像素没有随之保留。重建阶段实际承担了一个有信息损失的逆向问题。仅要求 Agent 仔细观察并填写结构化字段，无法消除这种损失。

目前运行时对结构与流程的保护较多，对视觉参数从原图到 PowerPoint 的传递保护不足。它可以忠实执行一份不够准确的语义图，也会通过默认值和文字缩小改变 Agent 提交的视觉意图。

## 主要架构问题

### 1. 生成自由度与重建表达能力没有形成闭环

`prepare_generation.py` 会传递设计和资源要求，但没有从实际渲染实现产生逐属性能力清单。生成图可以包含任意字重、透明叠层、阴影和复杂混排，重建器提供的可编辑表达更窄。

例如 `scene_to_pptx.mjs` 的普通 shape 路径主要发出几何、纯色填充和描边，没有接入一般形状的透明度、阴影与旋转。文本按整个框使用一套样式，缺少完整的局部富文本传递。Agent 即使看懂这些细节，也未必有能忠实表达的接口。

改进方向是让运行时声明真实能力，Agent 在选定目标前做重建可行性判断。对每个区域记录可编辑要求、实现路线和需要保留的视觉属性。不支持的属性要明确报告，交由 Agent 选择扩展表达、保留图片或修改目标。

这不要求固定模板，也不要求把生成器限制成一组简单卡片。约束应落在表示能力与编辑需求上。

### 2. Agent 的视觉判断被扩大成大量数值估计

语义图要求 Agent 自行指定边界、字号、字体、字距、圆角、层级、图标内缩和连接线参数。OpenCV 大部分工作发生在这些手工指定的框内。框外的信息不会帮助纠正框内的结果。

应拆开 Agent 的语义决定与工具的参数估计。Agent 指明对象和搜索区域，工具返回候选边界、线段、颜色样本、文字行与字体试排，Agent 通过叠图选取、修改或拒绝候选。数值拟合可以由代码完成，审美结论仍由 Agent 作出。

### 3. 文字适配目标偏向放得下

`text_fit.py` 使用 Pillow 文字宽度与近似行高进行适配，然后交给 Office 渲染。测量器提供的文字行框没有进入最终适配目标。字体候选与真实渲染的字形、基线和行宽也没有自动形成反馈。

`_authored_text` 默认会合并普通单换行。`_wrap` 只按空白分词。`_fits` 使用宽度和高度安全余量，整个 typography group 最后被最难适配的成员限制。最终适配可以一路减小到技术下限。

同组同字号是有用的设计约束，但一次错误的文本框或换行估计会影响整组文字。需要报告限制字号的成员、目标字号与实际字号、具体换行差异和拟合所用字体。Agent 应先判断问题来自框、字体或换行，再决定是否允许缩小。

建议先保留准确文本和观察到的行分配，再用真实渲染验证字体、字号、字距、行距和基线。缩小只是候选修复之一。

### 4. 视觉复核要求很强，复核工具提供的信息很弱

文档要求检查 overlay，但测量器当前 overlay 画的是搜索框与 ID，没有画出最终 layout box、visible box、轮廓或文字行框。几何修正又发生在绘制之后。

`make_visual_comparison.py` 负责并排展示，能够帮助整体观察，但没有直接提供局部配准叠图、逐实体差异或错误定位。Agent 需要在两张整页图片之间自行寻找所有偏差。

应提供搜索框、观测边界、选用几何三层叠图，以及目标与真实渲染的透明叠加、差异图和局部裁剪。像素差与边缘位移只做诊断证据，不产生美观或放行分数。

### 5. 冻结目标与冻结估计需要区分

保留原图构图是正确的。原图中的真实几何与 Agent 第一次估计的 bbox 却不是同一件事。当前 `geometry_adjustments` 仅允许移动，不允许修正尺寸。尺寸错误仍可通过修改语义图重测解决，但缺少同等清晰的修正记录和工具支持。

需要允许 Agent 在目标保持不变时修正测量模型，包括尺寸、文字框、轮廓和裁剪坐标，同时记录原值、证据和理由。只有目标本身发生变化时，才重新打开设计决定。

### 6. Profile 的权威来源有时被静默改写

`_base_style` 会把不符合配置的字体替换掉，把禁止的斜体关闭，并对不允许的文字颜色使用回退值。即使上游没有正确识别冲突，编译仍可能继续。

Profile 规则当然可以优先，但这种变化应当显式报告。Agent 应看到哪一条规则替换了哪一个原图参数，决定修改目标或调整经过授权的配置。静默纠正会使最终结果变化的原因难以追踪。

## 已确认的实现缺陷与风险

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| 中文无法正常参与断行拟合 | `_wrap` 使用 `paragraph.split()`。在 180 × 100 px 框内测试 27 个连续中文字，目标 24 px 被缩到约 8.33 px，仍为单行 | 中文页面可能明显丢失层级与密度。该数值是本机小实验结果，不代表所有字体 |
| overlay 没有显示实际使用的几何 | `measure_visual_scene.py` 绘制 `box`，随后才执行 `normalize_local_geometry` | Agent 可能审查了搜索框，却以为审查了最终测量结果 |
| 通用前景阈值容易测到子内容 | 实验用 200 × 100 px 灰色底和中央 80 × 20 px 深色块，得到边界 `[61,41,80,20]` | 若用 `opencv_visible` 表示整个卡片，会把内容边界当成容器边界。`agent_logical` 路径不受这一具体缩框影响 |
| 原图裁剪与摆放框可能不一致 | image 裁剪来自搜索框，摆放可来自 visible box，默认原图 crop 使用 fill | 两个框不一致时，整个搜索区可能被压入较小区域。需要独立的源裁剪坐标和目标坐标 |
| 轮廓坐标被猜测为局部或全局 | 渲染器对每个点检查 `x <= width && y <= height` | 同一轮廓的不同点可能被混用坐标系。实验矩形首点应为局部 `[0,0]`，却变成 `[100,100]` |
| 轮廓没有与 bbox 一起转换 | 场景编译器转换 bbox 与手工路径，直接传递 measured contours | 有缩放或页眉偏移时，轮廓与容器不在同一坐标系 |
| 原生 chart 调用缺失参数 | `addChart` 需要第五个 `pptx` 参数，主分发只有四个参数。按该调用复现 `TypeError` | 当前原生图表路径会在读取 `ChartType` 时失败 |
| 部分视觉属性没有完整传递 | 普通 shape 和 textbox 发出路径只消费有限属性 | 即使 Agent 提供更细描述，输出仍可能丢掉这些处理 |

这些问题中，中文换行、坐标转换和参数传递是机械缺陷。修复它们不会削弱 Agent 的创作自由。

## 对现有拼贴样例的观察

三个拼贴区域和整体版式得到较好保留。原生文字与箭头仍可见字形、字重、间距或路径端部的变化。样例记录了 21 个原生文本框、2 条原生曲线和 10 个图片对象。拼贴、纸张纹理、内嵌文字和手写字继续保留为图片。

因此，这个样例支持按视觉归属进行混合重建的方向。它不能单独证明全面原生重建能力，也没有覆盖中文换行、普通容器测量和原生图表。

## 建议的改造顺序

### 第一批，修复可证实的机械问题

1. 修复 chart 参数传递和轮廓坐标转换，禁止猜测坐标系。
2. 修复中文断行，保留显式换行，显示字体回退与整组缩字的具体原因。
3. 区分搜索框、观测框、输出框和图片源裁剪坐标，修复 overlay。
4. 对未支持的属性与配置替换提供明确诊断，避免静默丢失。

验证应覆盖最终 PPTX 渲染，不能只验证 JSON 和对象存在。中文、轮廓变换和图表各有一个小型端到端样例即可先建立保护。

### 第二批，建立 Agent 可使用的视觉修复闭环

1. 生成后记录逐区域原生与图片路线，并检查其可实现性。
2. 提供边界、文字行和样式参数的测量候选。
3. 对字号、字体和基线提供局部真实渲染试排。
4. 每轮修复提供全页与相关局部对照，并保留上一版供回退。
5. Agent 记录具体差异、影响对象、选择的修复和复核结果。

不需要新增长篇表格或更多审批状态。可以让工具自动填充现有字段，把 Agent 的输入集中在语义、候选选择和视觉取舍上。

### 第三批，建立有代表性的质量基线

建立中文与英文排版、轻底色卡片、原生图表、连接线图、透明叠层和复杂拼贴等小型样例。固定目标图片、编辑要求和已知局部难点，保留真实渲染对照。

测量报告可以包含行数、边缘位置、对象几何和字体替换事实。视觉验收仍由 Agent 实际看图完成。只有这些案例稳定后，再用多页自动生成验证编排、局部修订和整套一致性。

## 后续修复与项目完整性检查

文字处理进一步覆盖中英混排，并默认保留明确的人工换行。禁止行首的常见东亚标点与前一个词元保持在一起，英文单词保持完整。非有限数字和无效拟合步长会明确失败。最终字号直接传给 PowerPoint，避免渲染器再次按半点取整。已由其他对象承载的非发出文字不再参与字号分组和拟合。

文字分组报告新增无法容纳目标字号的成员、测量字体路径和 Profile 样式替换记录。这些证据帮助 Agent 解释变化，不能证明字体覆盖所有字符，也不能代替实际渲染检查。

图片裁剪使用实际选定的布局区域，并保存来源裁剪框。搜索区域裁剪修正为真实画布交集，拒绝完全越界区域。几何移动检查四条画布边界，轮廓、手工路径和图标摆放共同消费移动结果。实体标识生成文件名时进行编码，避免斜线产生意外子目录。声明必须发出的对象如果没有产生输出，编译会报告缺失。

原生输出保留测量得到的多个独立轮廓。条形图与柱形图使用明确方向，无箭头连接线保留无向外观。圆角后处理参数按页保存，避免不同页面上的同名对象互相覆盖。

PPTX 发出与后处理先在临时目录完成，全部成功后替换最终输出。后处理失败保留已有成果，且使用当前 Python 解释器。技能打包同样在完整检查后替换旧归档。JSON 序列化失败清理临时文件。历史归档补全逐页工作区和当前会话覆盖配置，设计签名能观察逐页目标的变化。整套组装拒绝场景页标识与清单不一致的输入。CI 的致命静态检查覆盖打包运行时。

新增 `tests/test_runtime_integrity.py` 覆盖这些边界。验证包含真实 OpenCV 测量、原生 PPTX XML、失败保留旧文件、独立打包、现有分发安装测试和本机 LibreOffice 实际渲染。双页样例确认独立圆角参数、两块分离轮廓和两种图表方向。连接线样例确认折线路径连续且没有箭头。

中文实际渲染进一步发现，本机无显式字体配置时，拟合器能找到中文字体，打包的 headless LibreOffice 却丢失全部中文。相同 PPTX 加入系统字体目录后恢复中文，定位为预览字体发现问题。默认 macOS 预览现在在临时目录生成字体配置，包含已有系统与用户字体目录，并记录字体环境来源。显式配置继续优先，其他操作系统保留原有字体发现方式。已补充配置优先级和环境隔离回归测试。

这一阶段的完整 Python 测试共 144 项通过，Node 测试共 24 项通过。10 个 JavaScript 文件的语法检查、致命静态检查和差异空白检查通过。配置、Profile 目录和技能边界检查没有阻塞事实，自包含技能包已生成。实际渲染、连接线叠加证据、中文修复前后图和技能包保存在 `output/architecture-audit-20260905/`。默认字体修复后的中文图与显式正确字体配置的图在本机逐像素一致，这一结果只描述该样例。

## 跨页一致性与生成输入的后续修正

咨询样例暴露了生成正文与公共页框混用的问题。现在由同一个画布解析模块从完整页尺寸扣除已启用的页眉和页脚，再将正文比例传入实际图像请求。生成器收到的内容、参考图、共享设计和附件都来自同一份已编译请求。图像编辑也继承这份请求，避免另外手写的提示词遗漏约束。实际渲染按正文区域对比生成图，公共页框在原生 PowerPoint 中检查。

仅统一大标题和决策栏仍会漏掉小型重复元素。Editorial 的系列标识在前三页被命名为 `field-note`，后两页变成 `folio`。它们承担相同功能，却分别使用了不同字体、字号、字重和字距。每页文字拟合满足了自己的输入，局部通过没有建立跨页一致性。

现行流程要求 Agent 在初期设计、生成候选和实际渲染后重新发现重复角色。角色没有固定白名单。Agent 将各页不同名称的实体对应到同一角色，决定共享样式和有理由的例外，并把选择写入实际语义图或配置样式。角色绑定本身不自动改变字体。重建后的原生属性与全页图像共同用于检查修改是否落实。保留的 Editorial 修订通过同一测量、编译和渲染路径校准系列标识，原始生成证据仍按历史来源保留。

这些改动区分了两种失败。参数丢失、错误比例和原生文件问题由运行时代码修复。漏识别重复角色、错误分组和视觉判断问题由 Agent 的工作方法和具体复核修复。不能让其中一种验证替代另一种。

## 尚未被证明的范围

有限检查无法证明整个项目没有任何缺陷。当前未对所有操作系统执行本机集成测试，未执行所有 PowerPoint 版本的打开、编辑和另存验证。连接线的连续原生对象已验证，移动关联形状后自动吸附的 Office 行为尚未验证。

文字拟合仍是基于本机字体度量的预测。中文断行修复不等于完整的 Unicode 排版与字体回退实现。不同渲染器的字形替换、基线和行高仍需要真实页面复核。

完整富文本、通用阴影、透明叠层等视觉表达能力尚未全面扩展。生成图缺失原生对象树和被遮挡内容的信息问题也继续存在。需要原生编辑的区域应在确定目标时检查实现路线，复杂纹理和内嵌图像内容可按既有语义归属保留图片。

这些范围应作为后续代表性用例和能力扩展的依据。不得把测试通过数量、像素差分或技能边界检查表述为视觉质量或全项目无缺陷证明。
